# DRIVE Platform 代码审查报告

审查范围：`apps/web`、`apps/admin`、`packages/shared`、`services/api`、`.github/workflows`、`render.yaml`、`docs`、git 历史与本地 `.env`。
审查方式：全量静态阅读；后端 `python -m compileall` 通过（exit=0），本地未安装后端依赖、无自动化测试。

> 结论：整体是一个「能跑起来」的毕业设计/演示级全栈项目，pom 组织（monorepo + 共享包）做得不错，但**存在若干可被利用的安全问题**，以及一批会影响真实使用的功能 Bug、时区/数据一致性问题和工程化缺口。下面按优先级列出。

---

## 一、P0 安全问题（建议优先处理）

### 1. 聊天 WebSocket 完全无鉴权，可冒充任意用户
- `services/api/app/modules/chat/router.py:322` `@router.websocket("/ws/{username}")` 直接信任 URL 里的 `username`，不校验 JWT。
- 任何人都能连接到 `wss://.../chat/ws/<任意用户名>`，以该身份收发消息、标记已读、撤回消息。
- 这是整个项目最严重的问题，README 的「待办 3」也承认了。

### 2. 管理员权限只靠用户名 == "admin"，且注册完全开放
- `services/api/app/modules/admin/router.py:15`：`if current_user["username"] != "admin": raise 403`。
- `services/api/app/modules/auth/router.py:22` 的 `/auth/register` 没有任何限制，用户名规则 `^[a-zA-Z0-9_]+$` 允许 `admin`。
- 后果：数据库里若还没有 `admin` 账号，**第一个注册 `admin` 的人就获得全部后台权限**；数据库也无 `role`/`is_admin` 字段，无法做真正的角色区分。后台账号与普通用户账号是同一套登录。

### 3. 本地 `.env` 含真实凭据
- `services/api/.env` 第 2–11 行包含真实 Neon 连接串、JWT_SECRET、Cloudflare R2 AccessKey/Secret。
- 已确认**未**被 git 跟踪（仅 `.env.example` 入库），`git log -S` 也查不到历史泄露。但文件客观存在于工作区，一旦打包/共享即泄露。
- 处理：立即在 Neon / Cloudflare 控制台轮换，并避免把工作区整体外发。

### 4. 图片上传无服务端真实校验
- `services/api/app/modules/chat/router.py:251-284`：仅按扩展名白名单校验，不校验真实 MIME/文件头，也不限制体积；`await file.read()` 一次性把整个文件读进内存。2MB 限制只在前端 `ChatView.vue:406` 做，可被绕过，存在任意文件上传与内存打爆风险。

### 5. JWT 有效期长达 365 天且不可吊销
- `services/api/app/core/config.py:11` 默认 `ACCESS_TOKEN_EXPIRE_MINUTES = 60*24*365`；`render.yaml:29-30` 也设成 `525600`。Token 一旦泄露可用一年，且无黑名单/刷新机制。

### 6. 聊天发送/读取不校验好友关系
- `send_direct_message`（`chat/router.py:300`）不对发送者与接收者是否好友做校验；`/chat/history/{friend}` 也不校验好友关系（只按 sender/receiver 过滤）。配合 #1，可给任意用户发消息。

## 二、P1 功能缺陷 / Bug

### 7. 刷新聊天页后会显示「空白会话」
- `apps/web/src/views/ChatView.vue:181` 用 `chatStore.activeContact` 初始化 `selectedContact`，但 `onMounted`（203-207）只拉好友列表、**不拉历史消息**。刷新（F5）后右侧进入聊天窗口却没有任何消息，必须重新点一次联系人。

### 8. 刚发出的消息无法撤回（直到刷新）
- `sendMessage` 推送本地消息时 `id: null`（`ChatView.vue:354`），撤回按钮条件是 `msg.self && msg.id`（`ChatView.vue:100`）。后端只把消息推给接收方、不回显发送方，所以本次会话内发出的消息永远拿不到真实 id，撤回功能实际只在「刷新后从历史加载的消息」上可用。

### 9. 发送按钮 disabled 逻辑写错（用了 &&）
- `ChatView.vue:122`：`:disabled="!messageInput.trim() && !chatStore.connected"`。应为「无内容 **或** 未连接」都禁用（`||`）。当前空输入但有连接时可点、断网但有文字时也可点，只是点击后被函数静默 return，属于误导性交互。

### 10. 后台大盘请求失败会触发渲染报错
- `apps/admin/src/views/DashboardView.vue`：`stats` 初始 `null`，`fetchDashboardStats` 失败时 `loading=false` 但 `stats` 仍为 `null`，模板 `stats.total_users`（第 16 行等）会抛 `Cannot read properties of null`。

### 11. 切换测验后答题状态残留
- `apps/web/src/views/QuizView.vue:109-110/152-154`：`challengeAnswers` 是同一个 `reactive({})`，`startChallenge` 只重置当前题目的 key，不清空上一个测验的 key。旧 key 非 null 会让「是否答完」校验（164-167）误判通过。

### 12. DRIVE 雷达图未在卸载时销毁
- `apps/web/src/views/DriveView.vue:82-103` 创建 Chart 实例，组件无 `onUnmounted` 销毁，反复进入会累积实例/内存泄漏。

### 13. 一个用户只支持一条 WS 连接
- `chat/router.py:293-295` `active_connections[username] = websocket`，同一用户开第二个标签页会顶掉第一个，旧标签仍显示「在线」但收不到消息。

### 14. `moments/count` 的 `since` 未校验
- `services/api/app/modules/moments/router.py:89-95` 直接把字符串塞进 `created_at > %s`，非法格式会 SQL 报错 500；且该接口**没有登录依赖**（信息虽少但对外公开）。

### 15. 根目录 `pnpm api` 启动脆弱
- `package.json:12` `"api": "python services/api/server.py"`。`load_dotenv()` 靠 python-dotenv 从脚本目录向上查找才能读到 `services/api/.env`；`app/core/config.py` 的 `env_file=".env"` 又是相对 CWD 解析。从仓库根运行时能否加载 env 依赖 dotenv 的隐式行为，换运行方式（uvicorn 直接起、或从其它目录）容易踩空导致 `DATABASE_URL` 校验失败。README 推荐 `cd services/api` 才是稳的。

## 三、P2 数据一致性 / 性能 / 架构

### 16. 时区处理全项目不一致（真实会导致时间显示错乱）
- 聊天：`chat/router.py:189,243` 硬编码 `+ timedelta(hours=8)` 转北京时间字符串。
- 动态/后台：`moments/router.py:26`、`admin/router.py:126` 用 `created_at.isoformat() + "Z"`，默认 DB 里的 `created_at`（`TIMESTAMP` 无时区，`DEFAULT CURRENT_TIMESTAMP`）是**服务器会话时区**的裸时间。Render 是 UTC 时凑巧对，本地（+8）就错；且假定 UTC 与聊天的 +8 两套逻辑并存。
- 前端 `formatLocalTime` 还会对已格式化的 `MM-DD HH:mm` 再 `new Date()` 一次（`ChatView.vue:331`），跨时区用户必然错。
- 建议：统一用 `TIMESTAMPTZ` 存 UTC，接口一律返回带 `Z`/偏移的 ISO，前端只做一次本地化。

### 17. 每个请求新建数据库连接，无连接池
- `services/api/app/core/db.py:10-12` `psycopg2.connect()` 每请求一条新连接；Neon serverless 连接数有限且建连贵，并发一上来就会超限/变慢。建议引入连接池（psycopg2.pool / SQLAlchemy pool / asyncpg）。

### 18. 明显的 N+1 查询
- 好友列表：`chat/router.py:164-200` 对每个好友再查未读数 + 最后一条消息（2N 次）。
- 好友测验列表：`quiz/router.py:148-165` 对每个好友再查一次我的得分（N 次）。
- 搜索接口已经做过联表优化（`search/router.py`），这两处没跟上。

### 19. 表结构没有任何索引
- `db.py` 的建表语句只有主键和少量 UNIQUE，`chat_messages(sender,receiver)`、`friendships(username/friend_username)`、`moments(created_at)`、`quiz_attempts(quiz_id,respondent)` 等高频查询列都无索引，数据量增长后全表扫描。

### 20. 列表接口无分页 / 无上限
- `moments` 全量返回（`moments/router.py:42-51`），动态多了会拖垮首屏；`search` 有 `LIMIT 15` 但没有 offset；`admin/users` 全量。

### 21. 多进程下聊天不可用
- `ConnectionManager` 是进程内内存字典（`chat/router.py:287-319`），Render 若开多 worker 或横向扩容，跨进程消息无法路由。要么单 worker 运行（当前 free plan 大概如此），要么换 Redis pub/sub（依赖里已引入 `redis` 但没用上）。

## 四、P3 工程化 / 可维护性 / 文档

- **无任何自动化测试**：`git ls-files` 无 `*.test.*`/`*.spec.*`，CI（`.github/workflows/ci.yml`）只做前端构建 + 后端 `compileall`，不跑测试。
- **后端依赖不锁版本**：`services/api/requirements.txt` 全部裸包名，部署随时可能因子版本升级挂掉；应加约束或 `pip-tools`。
- **无 lint/format 配置**：虽然有 `.eslintcache` 忽略规则，但仓库无 ESLint/Prettier 配置，代码风格全靠人工。
- **重复代码**：`openUserProfile`（HomeView / ChatView / SearchView 各写一份）、多处 `modal-backdrop/modal-card`、多处 `getCurrentTimeLabel` 与 `friend.unread` 维护逻辑重复，适合抽到 `@drive/shared` 或公共组件。
- **交互层全是 `alert()` + `console.error`**（70 余处），无统一 toast/错误提示，也无全局错误兜底。
- **无 404 兜底路由**：两套 router 都没有 catch-all，未知 hash 路由白屏。
- **建表内嵌在 `db.py`**，无迁移工具（Alembic），后续 schema 变更靠手写 `ALTER ... IF NOT EXISTS`。
- **后端启动吞异常**：`db.py:156-157` `init_global_tables` 捕获异常只打印，数据库连不上时服务照样「启动成功」，之后所有接口 500，排查困难。
- **文档瑕疵**：`docs/DRIVE.md:2-3` 有重复的「夏天吃西瓜」占位垃圾行；`apps/web/.env.development:2` 注释写着「生产环境」但文件是开发环境。
- **仓库杂物**：`apps/web/shot1.png`（47KB 截图）入库；`apps/web/reasonix.toml`、`.reasonix/*` 等工具元数据残留（`.reasonix/` 已被忽略但 `reasonix.toml` 仍跟踪）。
- **`README.md` 的「当前生产地址/近期重构说明」与 `docs/DEPLOY.md` 仍描述旧 Render 服务仓库**（DEPLOY.md:42 说 Render 还连着旧仓库 `drive-model-backend`），部署状态与代码不在同一仓库，易误导。

## 五、优先级建议（若要修）

1. **立刻**：轮换 `services/api/.env` 中的 Neon/JWT/R2 凭据；给 WebSocket 加 Token 校验（`?token=` 或首帧鉴权）；把管理员判断改成 DB 角色字段或至少限制 `admin` 的注册。
2. **高**：修 #7 刷新空白会话、#8 撤回 id、#9 按钮逻辑、#10 大盘空指针；统一时区方案；上传加体积/MIME 校验。
3. **中**：加连接池与索引；消除两处 N+1；给列表分页。
4. **长期**：补测试与 lint；抽公共组件；迁移工具化。

> 说明：以上均为静态审查结论，未在真实数据库/线上环境复现。若要，我可以按优先级直接改其中任意一批并给出 diff。

## 六、修复记录（本次已实施）

### 后端
- **WS 鉴权**：`chat/router.py` 的 `/chat/ws/{username}` 增加 `token` 查询参数校验（`decode_token(token) == username`），不匹配直接 1008 关闭；`ConnectionManager` 改为「用户 -> 多个 WebSocket」集合，修复多标签互顶；发送消息增加好友关系校验；新增 `msg_ack` 回填真实消息 id。
- **管理员角色**：`users` 表新增 `is_admin`；`admin/router.py` 改为查库 `is_admin`；`/auth/register` 禁止注册保留名 `admin`；新增 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 启动引导（`db.py::_ensure_default_admin`）。
- **上传校验**：`chat/router.py::upload_image` 改为限长读取（默认 5MB）+ 文件头魔数识别，不再信任扩展名。
- **JWT**：默认有效期由 365 天改为 7 天（`config.py`、`render.yaml`）。
- **时区**：全库 `created_at` 迁移为 `TIMESTAMPTZ`；新增 `core/timeutil.py::to_iso_utc`；删除聊天的 `+8` 硬编码与动态的 `+ "Z"`，统一输出带时区 ISO。
- **连接池**：`db.py` 使用 `ThreadedConnectionPool`，`db_cursor` 从池取/还连接。
- **N+1**：`chat/friends` 改为固定 3 条查询；`quiz/friends-list` 改为单条 LEFT JOIN。
- **索引**：为聊天、好友、动态、答题等高频列新增索引。
- **分页**：`moments` 列表增加 `limit/offset`；`moments/count` 增加 `since` 格式校验与登录校验。
- **健壮性**：`init_global_tables` 失败不再吞异常；`.env` 改为按脚本/模块绝对路径加载，不依赖 CWD。
- **依赖**：`requirements.txt` 增加版本约束。
